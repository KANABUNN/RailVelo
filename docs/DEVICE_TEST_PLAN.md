## 2. 導入と基本表示

### 初回10分：起動確認後の前面GPS・保存

本人用ビルド`0.5.0`（`500.7.1`）の導入・起動と、前面実GPSの精度・静止/歩行速度・グラフ表示、CSV保存、画面上のエラーなしは本人申告で確認済み。以下は再現や未報告項目の追加確認に使う手順であり、確認済み項目の再試験を一律に求めるものではない。10分は起動後の目安。安全な屋外の歩行者用スペースで、画面操作は立ち止まって行う。前面試験中はRailVeloを前面に保ち、画面をロックしない。同梱リプレイはR01で別途確認し、このGPS試験の前提にはしない。

1. RailVeloを前面に保ち、「実GPS」で記録を開始する。位置情報は「アプリの使用中」を許可、「正確な位置情報」をオンにする。初回に「常に許可」へ変更する必要はない。許可後は自動開始するため連打せず待つ。屋外で約1分静止し、GPS精度・速度・状態を見る。2分待っても更新されなければ状態を報告する。
2. 安全な場所を1〜2分歩き、立ち止まって速度の変化を確認する。その後約1分静止する。速度が無効な時の「—」や、線路から離れた場所での「判定中」だけで故障とは判断しない。静止中の大きな速度が繰り返す場合は記録する。
3. 「終了」→「記録を終了」。走行履歴から今回の「実GPSの走行記録」を開き、記録終了・最高速度・グラフを見る。短い間隔で有効速度を得た部分に連続線が描かれ、欠測や一時停止をまたいで線が結ばれていないか確認する。点だけの場合は連続線の確認済みとはしない。「CSVを共有」→「ファイルに保存」で、可能なら「このiPhone内」に保存し、開けるか確認する。メールや公開チャットへ送らない。

追加試験を行う場合は次の様式を使う。確認済み項目の再回答は不要。座標・住所・経路・CSV本体・位置が分かる画像は不要。エラーに個人情報があれば伏せる。背景・電池・列車での実走は別の試験とする。

標準Core Location更新はアプリ終了で停止する。OSのメモリ回収による終了、開発環境でのプロセス終了、本人による強制終了を区別して記録する。B06の模擬終了を実際のOSによる終了の検証と呼ばない。OS終了後の無欠測継続は保証しない。[Appleの標準位置更新仕様](https://developer.apple.com/documentation/CoreLocation/CLLocationManager/startUpdatingLocation%28%29?language=objc)

電池試験では同じ区間・時間・画面明るさで、前面表示とロック中を分ける。残量差、記録観測数、最大欠測秒、端末の熱状態を残す。開発用に接続できるMacがある場合はInstrumentsでCPU・メモリ・Energyを計測する。Windowsの処理時間やCIの性能をiPhone性能の代用にしない。

## 7. 門司港〜博多の実走

初回は短区間の前面記録で開始し、履歴とCSVを回収できたら背景・全区間試験へ進む。列車名・列車番号が分かる場合は個人用の試験メモへ残すが、アプリの未実装機能として扱う。

| 観点 | 記録・確認 |
| --- | --- |
| 区間と方向 | 博多方面・門司港方面の両方。起動後の捕捉までの時間 |
| 駅間距離と進捗 | 地図上の前後駅、距離の増減、進捗の連続性、終端の扱い |
| 折尾・並走・分岐 | 誤確定・長い判定保留・再捕捉時刻。停車中の方面変動 |
| 到着/発車/通過 | 現地観察との時間差。GPSだけの推定イベントと営業上の時刻を区別 |
| 通過列車 | 「次に通る駅」の表現を維持し、停車予定と混同しない |
| 停車・信号待ち | 駅停車と駅間停止の誤判定。駅付近の信号待ちは識別に限界がある |
| 受信環境 | トンネル、車内位置、地下・高架周辺、再捕捉までの欠測時間 |
| 速度 | 他の信頼できる観測と比較できる場合に参考差分を記録。列車制御用の正確さを認定しない |
| 長時間 | 保存観測数、電池、CPU/メモリ、クラッシュ、終了後の履歴参照 |

N02の代表線形に基づく距離は営業キロや実際の番線の走行距離とは差がある。地図の正解データがない観測で精度を断定しない。問題点は個人情報を除いたシナリオへ縮約し、再現fixtureと修正後の自動試験へ還元する。
