# 鉄道走行モニター 技術設計 v0.3

## 1. 継承と実装境界

前工程の `railmonitor_n02/output`、元SQL、生成・検証スクリプト、設定、品質記録を読み取り、必要な原本を `vendor/n02/` に保存した。v0.2元DDL・駅ID・原本ZIPを維持する。設計書v0.2本文そのものは今回指定されたフォルダーに同梱されていないため、元SQLと前工程 `docs/DESIGN_NOTES.md` に記録された設計対応を引き継ぐ。ライブラリ原本v0.2との逐語的な再照合は未実施。

v0.3はオフライン計算ライブラリである。Core Location、画面描画、永続化の操作、位置情報権限、バックグラウンド動作、列車別時刻表は計算部分に依存させない。新しい乗車は新しいMatcherインスタンスを作成する。

## 2. 構成

```text
Core Location → Observation → MapMatcher / Matcher → MatchResult → SwiftUI
                                  ↑         ↓
SQLite読取 / JSON → Network       グラフ   EventDetector
```

Python参照版：`network.py`（幾何・接続・読取）、`matcher.py`（観測検査・HMM・予測）、`events.py`（イベント状態機械）。Swiftは対応するCore、SQLite、Locationを別ターゲットにする。位置観測と正解データは別JSONLとして保存する。

## 3. データ契約

完全なキーと単位はルートの `CONTRACT.md` に記録する。SQLiteは `metadata / nodes / edges / routes / route_edges / stations / route_stations`。元v0.2データの保存先とは分離する。

線形はWGS84互換の緯度経度点列、エッジ距離と区間内累計距離は元のGRS80楕円体弧長を保存する。射影は各線分の周囲で局所的に計算し、その線分上の比率を累計弧長へ写す。GPS誤差・N02地図誤差・静的測地系変換の誤差を補償するものではない。

エッジは双方向、形状はfrom_node→to_node。接続はノードIDで表現し、座標上の交差・近接から推定しない。`route_edges` は駅距離計算に使う連続した向き付き代表経路。エッジの向きと路線の向きは別で、`route_direction = edge_direction × route_edge.direction`。駅距離は経路先頭からの累計距離。門司港中心の約123.436m手前に計算原点があり、駅間の差は元データと同一。

同一エッジを1路線内で複数回たどるループ経路は未対応で、ローダーが拒否する。将来は経路出現IDを導入する。全国を単一の平面座標系で計算しないが、極域・日付変更線をまたぐ線形は未検証。

## 4. HMM系列推定

状態は `(物理エッジ, エッジ上の進行方向, 路線属性)` と、その観測のエッジ上射影点。最近傍候補1本だけに固定しない。過去観測の事後分布を次の事前分布に引き継ぐ、オンラインのHMM前向きフィルターである。全走行終了後のViterbi再計算・固定遅延スムージングは実装していない。

1. 線分の緯度経度グリッドで近傍を探し、射影距離が `min(500, max(80, 3×水平精度))m` 以内の12エッジまでを候補にする。
2. 観測尤度は `−0.5 × (横ずれ / max(8m, 水平精度))²`。GPS速度が3m/s以上かつ速度精度が有効なときだけ、方位差40°を尺度とした尤度を追加する。
3. 遷移距離はエッジ上の移動とノード間のDijkstra最短路距離を組み合わせる。同じエッジの継続・小さな後退・反転を別扱いする。エッジは双方向であり、転轍器の通行規制までは表現しない。
4. 期待移動距離は有効なGPS速度×経過時間。速度が使えなければGPS変位を移動尺度として使う。実際の駅間距離・残距離はこの直線変位から計算しない。
5. 遷移は `−abs(経路距離−期待距離)/β`。`β=max(20m, .35×期待距離+前後精度+3×経過秒)`。反転、走行中の後退、路線属性の切替に罰則を与える。60m/sと位置精度に基づく距離上限を超える遷移や、非接続の遷移は除外する。
6. 過去状態からの寄与をlog-sum-expで合算、観測尤度を加え、24状態に制限して正規化する。対数計算で数値アンダーフローを避ける。最短路キャッシュは4096組に制限する。

低速での方向反転罰則は8、3m/s以上は4。これは停車中の方位揺れに対して直前の進行方向を保持するための既定値であり、実走で較正していない。

## 5. 確定と保留

3回以上の有効観測、捕捉後に20m以上動いた履歴、路線の周辺事後確率0.85以上、路線・方向の同時支持度0.8以上、最良点50m以内の位置候補支持度0.65以上、横ずれ `max(50m, 2×精度)` 以下を満たすと `matched` にする。移動履歴は再捕捉まで保持し、逆走して最初の位置へ戻っただけでは失効しない。代表経路上の方向・距離対応が存在することも必要。

満たさなければ `uncertain`。位置の最有力候補と候補配列は残し、確定路線・方向・前後駅・駅間進捗は空にする。近隣別路線や別経路では距離対応を整備していないため、候補を持てても確定結果は出さない。この保留を路線正解率の分母から隠さず、評価で確定率を別記する。

confidenceは位置支持度、路線支持度、路線方向支持度の最小値。候補内の相対値であり、GPSの真の誤差確率や路線の正解確率に較正されていない。地図に存在しない路線は候補にできない。uncertainty_mとstatusを併用し、confidenceだけで画面を確定表示しない。

## 6. 異常・欠測

| 条件 | 扱い |
| --- | --- |
| 非有限時刻・座標範囲外・時刻逆行/重複 | rejected。不正入力でHMMを更新しない |
| 水平精度なし/非正/150m超 | 実測マッチを行わず欠測として扱う |
| 速度が負、60m/s超、精度なし/負/8m/s超 | 速度とその方位の利用を停止。位置は独立検査 |
| GPS変位が60m/s×秒+精度余裕を超過 | 座標飛びとして候補更新を拒否 |
| 方位が負/範囲外、低速 | 方位尤度を利用しない |
| 実測間隔30秒超 | HMM・イベント履歴をリセットして再捕捉 |

予測は最後の確定実測を起点に、最後の速度と方向で最大15秒。`uncertainty=水平精度+5×欠測秒+0.5×欠測秒²` とし、120mを超えれば位置の確定を停止する。実際には精度10mなら約10秒で停止する。分岐先が一意でない場合や路線境界でも予測を停止する。予測点を次のHMM観測として入力しない。

予測は `predicted` とし、confidenceを時定数10秒で減衰させる。予測中、異常棄却中、再捕捉前には到着・通過イベントを発生させない。一定速度モデルは信号停止・トンネル内の減速を知ることができず、短時間でも誤差が生じ得る。

## 7. 前後駅と残距離

確定した経路上の累計位置と駅の順序を方向ごとに比較する。次駅までの距離は同じ経路上の累計距離差、進捗は直前駅から現在位置の距離/当該駅間距離。範囲は0〜1。終端を超えた架空駅は作らない。駅中心の直前から直後にかけて駅間ペアが切り替わるため、停車中の表示は駅イベントと併用して安定化する。

「直前駅」は位置関係上通過した駅であり、その列車の前回停車駅ではない。「次駅」は次に通る地理的な駅で、停車予定駅ではない。

## 8. イベント状態機械

確定した実測だけを入力し、観測が不確実・欠測になれば連続性を切る。10秒を超える実測間隔からイベント時刻を捏造しない。

| type | 既定判定 |
| --- | --- |
| arrival | 駅範囲の外側からの接近記録、直近30秒内の走行、中心からmin(50m,駅半径の半分)以内、停止速度0.8m/s以下、位置幅30m以内で12秒以上の停止 |
| departure | 到着判定済みの駅で、2m/s以上の移動が3秒以上継続し、停止位置から25m以上移動 |
| pass | 連続実測で駅代表点を同方向にまたぎ、両側で2m/s以上。駅候補範囲+20mを抜け、範囲内停止がなかったことを確認してから発行 |
| between_station_stop | 駅の候補範囲外で20秒以上停止し、その前に走行履歴がある |
| resume | 駅間停止後に2m/s以上の移動が3秒以上継続 |

arrival時刻は連続停止の先頭、departure/resumeは継続移動の先頭、passは中心をまたぐ前後の実測時刻からの線形補間。passの通知時刻は範囲外へ出た後になるが、イベントに保持する推定時刻は中心の通過時刻。欠測や範囲内停止は保留中のpassを取り消す。イベントconfidenceは判定時の支持度を0.95で上限とする。推定時刻を発車ベル・扉開閉・営業上の着発時刻と同一視しない。

駅の近くで初めて測位したまま停止している場合、接近履歴がないため到着を確定しない。駅端の信号待ちも到着中心範囲から除外する。中心近くの信号待ちなど、GPSと地理データだけでは識別できない状況が残る。実ホームの停止位置・実走の速度精度による調整が必要。

## 9. 評価・拡張

共通合成データは15の人工ネットワークシナリオと、N02全区間の順方向・逆方向走行の計17シナリオで構成する。乱数seedは固定し、観測と正解を別保存する。正解は元の線形上で生成するため、地図誤差を評価できない。路線/方向正解率は確定した観測を分母とし、確定率・起動時除外数・予測誤差を併記する。詳細は `evaluation.md` と `evaluation.json`。

PythonとSwiftは同一モデル・式・既定値を移植するが、実行比較が成功するまでは同等動作を保証しない。候補順序を含む比較ツールとmacOS CIで差分を検出する。Swift/iOS/実機の実行状況は `VALIDATION.md` を正とする。

全国拡張は地域ごとのグラフ、測地系・駅ID対応、路線重複属性、接続の一次資料による裏付け、複数代表経路、端末上の空間索引、背景動作と省電力を追加検証する。現段階は速度上限60m/sの在来線向けであり、新幹線へ適用する場合には速度上限とモデルを設定化し直す。
