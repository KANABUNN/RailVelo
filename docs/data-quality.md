## 今回の品質検査

今回のアダプターによる自動検査は **22/22 PASS_WITH_DOCUMENTED_LIMITATIONS**。`docs/data-quality.json` が個々の検証結果を保持する。

SQLiteの `edges.point_measures_json` は元の楕円体による頂点ごとの累積距離を保持する追加列。JSONの `point_measures_m` と完全一致し、PythonとSwiftが同じ区間内距離を利用できる。連続して2回再生成し、SQLiteのSHA-256が `6c3bd3760afd8920bfd4f7f26522316e4d641da44a1d25e493e9a6a38e491aa1` で一致することを確認した。元の前工程マニフェスト52ファイルもハッシュ不一致0件で確認した。

- ID重複、非数値、非正距離、物理形状の同一路線内重複がないこと。
- 線形とノード端点の完全一致、元の区間内距離の保存、117エッジの連続性、駅順と距離の単調性。
- GRS80楕円体による独立した距離再計算。元のPROJ測地距離とVincenty計算の最大差は **0.000050 m未満**。地図そのものの精度を示す数値ではない。
- SQLiteの定義による外部キー、整合性、JSONとの件数・線形・距離・駅距離の実データ一致。
- 別路線への接続や駅距離を捏造していないこと。

## 分岐・並走区間の扱い

元の代表経路に加え、別経路候補3本を同じ路線属性の候補として保持した。これらは代表経路上の駅距離を持たないため、候補に乗った場合の駅間距離・方向の確定は行わない。曲線の対応点を直線補間して駅距離を捏造しない。

前工程ではレビュー用に除外されていた、代表経路から150 m以内の近隣68地物（線路46、駅の線形22）も参照し、15の他路線候補を追加した。共有する元頂点で分割し、同一路線内で重複排除して60エッジとした。例として日豊線、山陽線、篠栗線、香椎線、新幹線、私鉄、地下鉄等が含まれる。これにより近隣線路の存在を候補比較へ反映できる。

**近い・交差するという理由で他路線を接続していない。** 同じ運営者・路線属性内で完全一致する元頂点だけを接続する。対象本線との接続、他路線間の転線、立体交差の接続、上下線や番線は未確認である。他路線は近接する部分だけで、駅順・代表距離・進行方向ラベルを整備していない。線区境界での本線から他路線への追跡は不確実となり、履歴リセット・再捕捉が必要になる場合がある。全国ネットワークとして完成したデータではない。

## 既知の差と残課題

[JR九州「2024年度末 線区別ご利用状況」](https://www.jrkyushu.co.jp/company/info/data/pdf/2024senku.pdf) の営業キロと、N02の駅代表点間弧長には次の差がある。

| 区間 | 営業キロ | N02代表弧長 | 差 |
| --- | ---: | ---: | ---: |
| 門司港〜小倉 | 11.0 km | 10.871707 km | -1.1663% |
| 小倉〜博多 | 67.2 km | 66.680726 km | -0.7727% |
| 全区間 | 78.2 km | 77.552433 km | -0.8281% |

営業キロと地図線形の距離は定義が異なる。誤差の原因や実走距離との差を特定できていない。営業キロに合わせて線形を伸縮していない。上表の差をGPS位置推定の誤差として扱わないこと。

門司・陣原・折尾には複数の駅線形がある。元データ35線形は保持したが、代表点は本線経路上を優先した。別番線の正確な停車位置との対応は未検証。折尾の非代表線形は代表点から線路距離方向で約317 mずれる。駅イベントのチューニングには実走と現地・公式設備情報による確認が必要。

データ座標はJGD2011（EPSG:6668）。前工程で固定したEPSG:4326変換はPROJのnoopで、公称精度1 m。近隣追加線形も同じ数値を再利用する。測地系の精度1 mはN02線形・端末GPS・推定結果の精度を保証しない。

駅範囲はN02の「駅線形」を投影した値。半長+20 mを30〜250 mに制限した半径は推定用の設定であり、測量済みホーム境界ではない。半径内の停車だけを駅到着と解釈しない。

## 再現

作業ルートで次を実行する。

```powershell
python scripts/build_network.py
```

標準ライブラリのみ。入力DBと原本ZIPのSHA-256が変わると失敗する。新データへの更新時は元ファイルを無条件で置き換えず、駅ID・線形・接続・品質差分を確認して設定の期待ハッシュを更新する。

前工程自体から再生成する場合は Python 3.12 と `vendor/n02/requirements.lock.txt` のGIS依存を用意し、`vendor/n02/README.md` の手順に従う。元の `output/` を上書きせず `--out` で別フォルダーを指定する。原本ZIPを同梱しているため再取得は不要である。前工程の取得スクリプト `vendor/n02/scripts/fetch.py` は将来の取得用として保持する。

```powershell
python vendor/n02/scripts/validate_rail_db.py vendor/n02/output/rail_jrkyushu.sqlite --report docs/upstream-validation.json
python vendor/n02/scripts/test_topology.py
```

この2本は前工程のGIS依存が必要。今回の再実行では、既存の前工程Python 3.12仮想環境を読み出し利用した。仮想環境や第三者実行ファイルは納品フォルダーへコピーしていない。
